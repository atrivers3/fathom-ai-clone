This error happens because npm requires all package names (the `"name"` field in `package.json`) to be lowercase, URL-safe, and contain no spaces. When you run `npx create-next-app@latest .`, Next.js defaults the package name to the current folder name (`"Fanthom ai"`), which npm rejects. Additionally, the folder contains a typo (`Fanthom` instead of `Fathom`).

You have two clean ways to resolve this:

---

### Option 1: Rename the folder to `fathom-ai` (Recommended)

This fixes both the naming restrictions and the typo permanently.

Because Windows locks folders when processes (like Antigravity or the background capture daemon) have open handles in them, follow these steps:

1. **Stop the background capture process**:
   In PowerShell:
   ```powershell
   Get-Process python | Stop-Process -Force
   ```
2. **Close Antigravity** (to release IDE workspace file locks).
3. **Rename the directory** in File Explorer or PowerShell:
   ```powershell
   Rename-Item -Path "C:\Users\A-J Technologies\Desktop\Fanthom ai" -NewName "fathom-ai"
   ```
4. **Reopen `C:\Users\A-J Technologies\Desktop\fathom-ai`** in Antigravity.
5. **Restart the capture daemon**:
   ```powershell
   Start-Process -FilePath "python" -ArgumentList @("-u", "scripts/agent_capture.py", "--watch") -WorkingDirectory "C:\Users\A-J Technologies\Desktop\fathom-ai" -WindowStyle Hidden
   ```
6. **Initialize Next.js in the root**:
   ```powershell
   npx create-next-app@latest . --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --disable-git
   ```
   *(Since the folder is now `fathom-ai`, Next.js will accept it immediately).*

---

### Option 2: Initialize Next.js in the current folder without renaming

If you prefer **not** to close your IDE or rename the root folder right now, you can bypass the restriction by bootstrapping Next.js in a temporary subfolder and moving the files to the root:

1. **Bootstrap into a temporary subfolder named `fathom-ai`**:
   ```powershell
   npx create-next-app@latest fathom-ai --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --disable-git
   ```
2. **Move all generated files into the root and remove the temporary folder**:
   ```powershell
   Get-ChildItem -Path "fathom-ai" -Force | Move-Item -Destination "." -Force
   ```

3. Your `package.json` will now have `"name": "fathom-ai"`, and Next.js is configured at the root of the project while preserving your existing git history and `.agent-logs`.

### Root Cause Analysis

1. **Supabase PostgreSQL Table Grants & RLS Policies**:
   - In Supabase, enabling RLS on tables created in the SQL Editor requires explicit PostgreSQL privileges (`GRANT ALL ON TABLE public.meetings ... TO anon, authenticated, service_role`). Without this grant, the `anon` role is blocked at the database level.
   - Upsert queries (`INSERT ... ON CONFLICT DO UPDATE`) require distinct, permissive policies for **both** `INSERT` and `UPDATE`. Single umbrella policies can cause PostgreSQL to reject the update phase with `new row violates row-level security policy for table "meetings"`.
2. **Silent Failure in React Context (`MeetingContext.tsx`)**:
   - `addMeeting` previously had a `finally` block that optimistically added the new meeting to local React state even when `POST /api/meetings` failed. On page refresh, because the record was never saved to PostgreSQL, it disappeared.
3. **No Await / Error Reporting in Recording Modal**:
   - `RecordMeetingModal.tsx` did not await the persistence outcome, had no saving state indicator, and closed immediately even when the database rejected the write.
4. **API Route Error Propagation**:
   - `POST /api/meetings` lacked granular error checks on child table upserts (`participants`, `transcript_segments`, `action_items`, `highlights`), masking child relation write failures.
